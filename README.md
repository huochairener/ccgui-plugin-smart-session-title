# 智能会话命名（smart-session-title）

CC GUI 插件：每轮对话结束后，自动为会话生成一个**带 emoji 前缀的简短标题**，替代官方"第一条消息原样截断 80 字"的自动命名。

## 工作方式

1. 监听事件总线 `usage://updated` / `usage://done`，按会话防抖 8 秒合并一轮内的事件（与官方 auto-title 相同的触发模式，支持全部引擎）
2. 用 `node`（`exec:node`）读取 `~/.ccgui-next/app.db` 的会话全文索引——payload 全部内嵌在 `-e` 脚本里，不依赖命令行参数传递
3. **AI 模式**（默认）：经 `ctx.agent.start` 起后台只读轮次让模型起名（默认跟随会话引擎，可固定引擎/模型），标题自带一个贴合主题的 emoji；失败或超时自动回退**本地规则**——清洗第一条用户消息（去盘符路径、代码块、斜杠命令、客气前缀）后智能截断，emoji 按关键词映射挑选（🐛 修复 / 🚀 部署 / 🎨 前端…，无匹配时用 💬）
4. 标题写入 `sessions.custom_title`，调 `ctx.sessions.refresh()` 让侧栏立即刷新

手动改名的会话永远不会被覆盖。

### 命名轮次不会留下对话记录

引擎（pi / omp / codex / claude 等）每次被拉起都会把那次调用落盘成一份会话记录，
宿主的历史扫描器再按「这份记录的 cwd 是否属于某个已登记工作区」把它收成侧栏会话。
命名轮次如果沿用被命名会话的工作区，侧栏就会多出一条标题为「你是对话标题生成器…」的对话。

本插件把命名轮次跑在一个**不属于任何已登记工作区**的隔离目录里（优先
`<插件数据目录>/naming`，不可用时退回系统临时目录），扫描器归属失败 → 侧栏不会多出对话；
轮次结束后再把那份 transcript 自身删掉（只删「文件名含本次轮次 sessionId 且刚写入」的文件，
不跨引擎扫盘）。若两个候选目录都落在已登记工作区内，直接跳过 AI、用本地规则，
**不会退回到「污染侧栏」这条路**。

> 前提：`exec:node`。清理只作用于本插件自己发起的轮次产生的文件，不碰用户会话。

## 状态反馈（右下角状态栏）

- `✦ 会话命名中…` —— 正在命名
- `⚠ 命名失败` —— 出错常驻显示，**鼠标悬停看原因**，点击进设置页；下次成功自动消失
- `✓ 已命名：xxx` —— 成功提示，6 秒后消失

所有步骤写入调试日志（设置页可见最近 12 条，完整文件在插件数据目录 `debug.log`），排障不靠猜。

## 安装

1. CC GUI 侧边栏 →「插件」→「从本地目录安装」
2. 选择本目录（包含 `manifest.json` 的这一层）
3. 依赖系统 PATH 里有 `node`（≥ v22.5；本机为 v24.4.0，已由其他插件的 node 调用验证可用）

## 使用

- **自动**：正常聊天即可，每轮结束 8 秒后侧栏标题自动更新
- **手动**：会话列表右键 → 「智能命名（AI 重新起名）」/ 「恢复默认标题」；命令面板搜「智能命名」可给最近会话起名
- **设置**（插件页 → 智能会话命名）：
  - 命名方式：AI 智能命名 / 本地规则 / 关闭
  - 标题 emoji：开启 / 关闭（只影响之后的命名；emoji 不计入最大长度）
  - 命名引擎：留空 = 跟随会话引擎；可固定 claude / codex / grok / pi / codebuddy 等
  - 命名模型：留空 = 引擎默认模型
  - 标题语言 / 最大长度（8–60 字，不含 emoji 前缀）
  - **「测试完整链路」**：检查 node 与数据库，并为最近会话实际触发一次命名
  - 底部实时显示调试日志与最近错误

## 出问题时怎么排查

1. 打开插件设置页，点「测试完整链路」——每一步的成功/失败都直接显示
2. 看右下角状态栏的 ⚠ 提示（悬停显示原因）
3. 设置页底部有完整调试日志（含每次事件触发、node 调用、AI 轮次、写入结果）

## 迭代 / 卸载

- 改完代码后重新走一次「从本地目录安装」即可热重载（同 id 覆盖，配置保留），无需重启应用
- 卸载在插件页操作；插件数据保留 30 天

## 与官方 auto-title 的差异

- 官方插件依赖 `exec:python3` 读库——Windows 上若只有 Microsoft Store 的 python3 占位 stub 会一直"生成失败"；本插件用 `exec:node`（node:sqlite 内置，零依赖）
- 官方只支持 codex / omp / pi / claude 四个引擎；本插件**触发与写入**按引擎无关设计，grok / codebuddy 等同样能自动命名
- 命名轮次不落对话记录（见上节），官方插件的 CLI 调用会在工作区里留下会话历史

### 关于 AI 命名的引擎支持范围（实测口径）

宿主对插件自起的只读轮次（`ctx.agent.start` + `readOnly: true`）有引擎白名单：
只有 **Pi** 完全可用；Codex 的隔离只读规划目前要求 macOS，Claude / Grok / CodeBuddy 等会直接返回不支持。
因此：

- **Pi 引擎**：AI 智能命名生效（含 emoji 语义挑选）
- **其他引擎**：AI 轮次起不来，自动回退本地规则命名——仍然会自动命名，只是标题来自关键词规则而非模型
- 「触发 + 写库 + 侧栏刷新」这套机制本身对所有引擎一致，不受该白名单限制

想让非 Pi 引擎也走模型命名，可在设置页把「命名引擎」固定为 `pi`（前提是本机装了 pi 并已登录）。
